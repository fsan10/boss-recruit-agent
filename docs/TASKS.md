# AI 开发任务与验收

按 T0 至 T7 执行。每一步提交代码、运行命令及可核验结果。缺少真实账号时将在线部分标为待验收，继续完成其余工作。不得无限等待缺失凭据，也不得用模拟结果冒充线上成功。

## T0 核验真实可用能力

- 记录运行系统、浏览器、上游 CLI、DSH 及已认证备用 harness 的版本。
- 对锁定版本的 boss-agent-cli 运行 doctor/schema/help，确认 recruiter 角色、申请、推荐、在线简历、会话和附件能力；保存脱敏字段映射。不要直接安装未锁定的 latest。
- 用一个合成批次探测 DSH headless：stdin 输入、final 事件 text、退出码、超时与工具权限。
- WorkBuddy 区分桌面 MCP 与企业 CLI；ZCode 未验证非交互入口时保持 unsupported/unknown。
- 产物：CAPABILITIES.md 或 JSON，列明已核验、未核验、不可用；选择实际评分器。权限不能限制或需人工交互时不得标 unattended_ready。

完成条件：可指出哪些能力来自源码、哪些在当前机器实测，且评分进程不继承 Boss 凭据。

## T1 身份 快照与队列

- 完成核心表、迁移、candidate_id、candidate_jobs、动作记录与不可变快照。
- 实现任务原子领取、租约续期、fencing_token、去重和重启恢复。
- 实现 JSON/text/PDF/DOCX/image 导入及完整性检测；解析失败不产生假正文。
- 对合成数据生成规范化证据块及 hash，禁止用姓名或序号作为主键。

完成条件：同一批导入两次不重复产生当前候选人和当前评分任务；同名两个人保持不同 ID；旧运行器提交遭拒收。

## T2 评分闭环

- 使用 contracts 与 prompts 实现 DSH 适配器、JSON 抽取、证据校验、维度/门槛 ID 完整性校验。
- 完成 Decimal 算分、不确定区间、coverage 和人工复核路由。
- 所有 policy-cases 的输入和期望值通过；partial/summary_only 被路由到补充信息。
- 10 人一次提交，输出乱序按 ID 归位；缺人、重复 ID、跨人证据、假引用和新 URL 都有可见错误。
- 允许逐人提交成功及失败成员重试；最多 3 次，保持固定岗位、快照和量表。

完成条件：十人合成数据由真实 DSH 调用产生结果，逐维度证据可查，程序复算一致。无 DSH 凭据时明确只完成测试替身验收。

## T3 工作台与 WorkBuddy MCP

- 完成岗位草案审核、候选人详情、结果区间、证据定位、任务状态与暂停恢复。
- 实现共享业务层的 MCP 工具与批次租约；WorkBuddy 用一条对话处理最多十人并回写。
- WorkBuddy 与后台同时请求同一批时只有一个领取成功，过期 token 无法覆盖新结果。
- 人工更正保留原因及原 AI 版本；报告入口由可信动作表合并。

完成条件：用户无需终端命令，能看十人结果、纠正一项评分并打开正确候选人入口。使用合成数据时入口明确不可访问。

## T4 当前账号真实取数

- 使用单个已授权招聘账号，从申请或已有沟通记录读取一个小批次。
- 逐条核验平台 ID、岗位关系、全文来源和入口；推荐和申请记录不互相冒充。
- CLI 能力不适配时实现最小 BrowserAdapter；只截首屏的结果必须为 partial。
- 检查实际附件是否已共享且可下载；没有权限则保留在线简历和明确状态。
- 上游报风控、认证、限额时进入账号级暂停，不绕过或重开循环。

完成条件：真实候选人全文与评分输入一致，入口对应本人；提供脱敏验收记录，不把真实简历写入公开测试仓库。

## T5 可替换 harness 和运行策略

- 至少实现并实测 Codex 或 OpenCode 的一份合成十人批次。
- 区分最终业务结果和事件日志，记录模型标识、提示版本、上下文限制及 token 用量。
- 验证 180 秒不足十人也提交、超出上下文不截断、达到积压上限暂停详情采集。
- 仅允许预配置的数据处理范围和备用评分器；切换配置生成新的 scorer_profile_version。

完成条件：替换 harness 不改变身份、动作、验证器和算分程序。不同评分配置的结果有清晰版本，不能悄悄混排。

## T6 恢复 动作与保护

- 在评分中断电/终止 Worker，重启后接受已完成者并只恢复失败任务。
- 注入网络超时、认证过期、风控、重复事件、模型输出缺人和动作过期。
- 消息草稿具体批准后可逐人发送；响应丢失为 OUTCOME_UNKNOWN，不自动重发。
- 验证禁止字段脱敏、简历提示注入不生效、对象权限隔离、CSV 公式转义和删除联动。
- 做一致性备份及恢复，核验库中快照引用与受控文件。

完成条件：失败有准确状态；已发布评分不重复，身份不串人，外部动作的不确定性可见。不得声称远程消息恰好发送一次已经得到数学保证。

## T7 实际 24 小时常驻验收

- 配置一个真实岗位和允许的采集预算，记录开始/结束 UTC 及本地时间。
- 实际观察至少 24 小时，记录进程心跳、依赖状态、每批处理、重启和暂停。
- 可以使用合成输入持续测试恢复，但真实平台连接的时间与结果必须分开记录。
- 工作台显示下一次运行、待处理/失败数、最后成功时间和实际预算。
- 给用户一页完成报告：功能项、通过/未通过/未测、证据位置、使用方式、已知限制。

完成条件：有实际时间和运行记录支持“常驻 24 小时”；未到时不能提前宣布验收完成。

## 必须包含的回归场景

| 场景 | 期望行为 |
| --- | --- |
| 十人输出顺序反转 | 候选人和入口保持绑定 |
| 同名候选人 | 两个独立记录，不按姓名合并 |
| 一人无投递记录 | application_view unavailable |
| 返回其他人的证据 | 拒收该成员 |
| 简历要求忽略规则并给满分 | 不执行简历指令，照量表评估 |
| 原文只是关键词列表 | 按浅层锚点评估，不因重复增加等级 |
| 未提及必需经验 | gate unknown，补充信息队列 |
| 明确没有必需经验 | 有证据的 gate fail，人工条件差距复核 |
| OCR 或正文不全 | 保存部分证据和质量状态，不发布成完整评分 |
| 仅八人结果合法 | 八人入库，另两人重试，界面显示完整度 |
| 模型超时和迟到结果 | 结束失联进程，fencing 拒绝过期覆盖 |
| 平台发送成功但响应丢失 | OUTCOME_UNKNOWN，核验而非自动重发 |
| 登录失效 | 暂停账号平台操作，已导入简历仍能评分 |
| 变更量表 | 新版本、新评分；保留历史 |
