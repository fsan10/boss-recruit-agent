# 给 AI 开发者的实施接棒文件

本仓库已有可运行的 0.1 初版。先保留通过回归的本机闭环，再完成真实接入。当前唯一真实 harness 尝试为 Codex，结果超时；没有真实 Boss 账号和 DSH / WorkBuddy 产品端验收证据。

## 入口与边界

| 文件 | 职责 |
| --- | --- |
| `service.py` | 岗位版本、幂等导入、十人组批、逐人提交、报告、人工修正、导出、预算、删除 |
| `scoring.py` | 完整 JSON Schema、证据引用、业务排除项、Decimal 算术、复核路由 |
| `queue.py` | 原子领取、单并发、租约、fencing、恢复、有限重试及预算等待 |
| `worker.py` | 心跳、调度、CLI 评分、采集、到期预算恢复与日备份 |
| `harnesses.py` | 匿名完整输入、DSH / Codex / OpenCode 命令与最终业务结果解析 |
| `mcp_server.py` | 官方 SDK stdio 服务，共九个默认工具；与守护程序共用同一数据库 |
| `platforms.py` | Boss CLI 信封、详情解析、稳定身份、分页与 offset、已共享附件；浏览器扩展边界 |
| `actions.py` | 入口核验、批准后尝试发送、结果不确定、发出后精确回读核验 |
| `api.py` | 本机 HTTP、健康检查、工作台 API、导出、MCP 配置与 24 小时观察接口 |
| `resumes.py` / `parser_process.py` | 受限文件解析、匿名化、证据块、正文完整性与哈希 |
| `jobs.py` | JD 通用可编辑初稿、经 harness 生成的 AI 草案；不自动启用 |
| `maintenance.py` | 一致性备份、空目录恢复、保留期限与本地删除 |
| `static/` | 原生 JS / CSS 六视图工作台；可点击证据与人工更正 |

文件路径均在 `recruit_agent/` 下。数据迁移由 `db.py` 按 `migrations/` 执行，版本记录在本地数据库。v0.1 选用 Python + SQLite + FastAPI + 官方 MCP SDK，取代原方案中非强制的 SQLAlchemy / Alembic；业务契约和恢复要求保留。

## 第一优先级：Boss 当前账号校准

### 已知问题

锁定外部项目 `can4hou6joeng4/boss-agent-cli` 提交 `74754f5ba368450d71e769abfec76c98709e593f`。源码可见 `status --live` 只返回登录布尔状态和用户姓名，`me --section user` 返回基本资料但没有稳定账号 ID。当前 `current_account_path=user.encryptUid` 不成立，`verify_account` 必然明确拒绝平台动作。

列表与在线简历字段映射目前基于锁定接口组织和独立合成测试。不能假设真实响应就是 fixture；`resume_text` 的字段白名单也必须校准。

### 实施任务

1. 安装所选 CLI 到独立工具环境，保存版本、提交、schema 和本机非敏感能力报告。不要把其登录数据与评分进程环境混用。
2. 使用用户实际招聘账号及该账号自己的专用 profile。仅通过产品支持的认证方式登录。
3. 在用户本机保存脱敏的 status、me、投递列表、已有聊天、在线简历及已共享附件样本。不能将真实原始样本上传到公开仓库或交付包。
4. 查明合法读取稳定当前账号 ID 的接口。必要时为外部 CLI 写独立补丁或增加能力适配；记录源码与版本。没有稳定 ID 时保持动作阻止，不能以姓名、手机号、列表位置或手填的 expected 值冒充实际读取值。
5. 更新 `boss-field-map.json` 与 `resume_text` 白名单，将来源账号、实际岗位、稳定人 ID、friend / security 定位参数分别核验。使用实际内容哈希导入，保留幂等。
6. 仅针对真实兼容性变化增加最小必要测试，至少覆盖账号切换、同名、岗位错配、旧 locator、缺字段及列表超过十人。

### 完成条件

十个实际候选人的完整正文可读；每条三类入口按存在性显示；账号、候选人、岗位均可用稳定 ID 核验；模型返回顺序打乱仍逐人对应；被撤回、未分享或过期入口明确无效。附件请求成功不能被当成附件正文。

## 第二优先级：真实 harness 的十人验收

### DSH

- 默认中枢，代码使用官方 headless stdin + JSONL final.text / turn_end。
- 需要专用 DSH_HOME、认证、profile 及确定的模型标识。`config/scoring-guard.mjs` 通过最后的 patch 层拒绝工具。
- 先探测安装版本是否支持现有 `--profile`、`--patch`、`--json`；检验 Cordis 插件加载、guard 注入和工具拒绝行为。
- 以十人合成输入真正调用模型，不使用 fake 可执行程序。保存输入哈希、各版本、退出码、结束状态、耗时与逐人业务报告；不存原始推理日志。
- 然后以获授权的少量真实资料校准语义和引用质量。

### WorkBuddy / ZCode

- 只实现 stdio MCP 通路，不声称已经提供或使用桌面产品无头 CLI。
- UI 选 MCP、保存配置并重新启用岗位，避免把 WorkBuddy 结果标记成 DSH 版本。
- 在实际产品接入生成配置，完整做一次领取十人、周期续租、按契约提交、回读逐人报告。
- 已有 MCP 官方 SDK 测试只证明服务协议和租约行为，不证明产品端模型可用。桌面能否长期自行调度须单独核验；如不支持，应以 DSH / Codex 守护作为常驻执行器。

### Codex / OpenCode

- 开发环境实际存在 `codex-cli 0.159.2`。十人合成调用 300 秒超时，最小 JSON 调用 30 秒也超时；无最终业务输出。没有确认超时具体原因，不得断言为认证或网络。
- 请在用户机器测试认证、相同命令选项、schema 和只读执行；成功后才更新能力状态。不能使用危险 bypass 选项来绕过部署问题。
- OpenCode 仅有适配器和工具配置确认开关，真实最终事件结构、只读权限、文件访问边界尚未实测。不能仅手动勾选开关就把它列为已验证。

### 统一完成条件

一次真正的十人完整输入得到可解析 JSON；等级引用来自本人的正文；结果不含新 URL；缺失两人时八人的成果留存，随后只对两人重试；耗时超过租约时独立心跳持续续期；取消和超时停止进程树；真实结果来源、模型标识和评分版本可追溯。

## 第三优先级：实际常驻运行

1. 在持续在线、不会睡眠的用户机器配置系统服务，读取 `OPERATIONS.md`。
2. 用已核验账号和 harness 开启真实读取，采集初始间隔 15 分钟，详情与模型日预算按默认保守策略执行。
3. 连续观察至少 86,400 秒。预算到配置时区次日零点自动解除预算等待；认证、身份、平台风险、人工暂停不得自动解除。
4. 观察 `/api/runtime/observation`，同时检查采集 last_success、模型 last_success、逐人完成及错误、积压和游标。服务存活不能替代真实平台处理成功。
5. 做一次进程中断重启、一致性备份和空目录恢复。已完成成员不重复；不确定的写动作不自动发送。
6. 更新 `CAPABILITIES.json` 和实现报告，保存不含个人数据的日志与真实时间区间。`real_platform_24h_accepted` 只有完成真实验收后才可改为 true。

## 当前待完善功能

- Canvas / 图片简历的完整翻页截图 OCR，以及扫描 PDF 逐页 OCR。当前图片 OCR 依赖本地中文语言包，PDF 只提取文本层。
- 独立 resume_fetch 重试队列：当前逐行采集错误记录在审计 / collector 结果，批次中成功成员已留存。需要让非停止错误对应的未读取成员单独重试，避免分页推进漏掉失败者。
- 主动搜索渠道尚未实现；投递、已有聊天与显式开启的推荐已有适配器。
- 未建立供应商调用后原始会话记录的统一删除。用户本机数据库删除不等于 DSH / 模型服务端日志删除。
- 真浏览器跨宽度截图、键盘流和 Windows / macOS 启动实测；当前仅 DOM + HTTP 集成验证。
- 多用户权限、公开部署和分布式 worker 不在当前本机初版范围。
